# Frame — Video & Audio Recorder

Chromebook の Chrome で、内蔵／USB カメラとマイクを個別に選んで録画・録音する静的 Web アプリです。録音のみならカメラなしで MP3 を保存できます。動画や音声の外部アップロード、分析 SDK、外部フォントはありません。

## 起動

Python 3 があれば、追加インストールなしで動作します。

```sh
cd /workspace/Chromebook-Video-Recorder
python3 -m http.server 8000 --bind 0.0.0.0
```

ローカル開発では `http://localhost:8000` を Chrome で開きます。Chromebook で直接試す場合は、このフォルダーを Chromebook の Linux 開発環境にコピーして同じコマンドを実行できます。Linux 環境がない Chromebook では、静的ホスティングに配置した **HTTPS** のサイトで使用してください。LAN 内の HTTP アドレスではカメラ権限を利用できません。GitHub Pages の公開手順は下記を参照してください。

`npm start` でも起動できます（Node.js と Python 3 が必要）。ビルドやアプリ実行用の npm 依存はありません。

## GitHub Pages で公開する

ビルド不要です。リポジトリの **Settings → Pages → Build and deployment** で次を設定します。

1. Source: **Deploy from a branch**
2. Branch: **main**、フォルダー: **/ (root)**
3. **Save** を押し、GitHub のデプロイ完了を待つ

公開後の URL： https://playa2021git.github.io/Chromebook-Video-Recorder/

公開が完了すれば、Chromebook の Chrome から URL を開くだけで使えます。初回はカメラ・マイクの権限を許可してください。インストールや Linux 環境は不要です。HTTPS が提供されるのでカメラ API を利用できます。`.nojekyll` により静的ファイルをそのまま配信します。

Pages を有効にするにはリポジトリの管理権限が必要です。リポジトリが非公開の場合は、GitHub のプランや組織ポリシーにより Pages を利用できない場合があります。リポジトリの公開範囲はこの作業では変更していません。

## 使い方

1. 「動画を録画」を選び、USB カメラやマイクを接続。「カメラ・マイクを接続」を押し、ブラウザの権限を許可します。
2. カメラ／マイクを選び、1080p／720p／480p とステレオ／モノラルを設定します。
3. プレビューの下にある **実際の入力解像度と入力 ch 数**、L/R メーターを確認します。
4. 録画を開始。一時停止・再開・停止ができます。
5. 停止後に再生確認し、「端末に保存」で WebM ファイルを Chromebook にダウンロードします。Chrome の設定に応じて保存場所を選択、またはダウンロードフォルダーに保存されます。ダウンロード一覧で保存完了を確認してください。

動画・音声は停止まで、停止後もページから削除するまで **ブラウザのメモリ** に保持されます。自動的にディスクへ保存する方式ではありません。ページを閉じる前に必ず保存してください。長時間録画ではメモリ不足になる可能性があるため、分割して保存してください。

## 録音のみ（MP3）

1. 画面上部で **「録音のみ」** を選びます。録画から切り替えた場合、使用中のカメラを停止します。
2. **「マイクを接続」** を押し、マイクだけの権限を許可します。カメラのない PC やカメラが拒否されている環境でも使えます。
3. マイクとステレオ／モノラルを選び、入力チャンネル数・メーターを確認します。
4. **「録音をはじめる」** を押します。一時停止・再開が可能です。
5. 停止後に音声プレーヤーで確認し、**「端末に保存」** で `.mp3` をダウンロードします。

音声 PCM を AudioWorklet で取得し、Worker 内の lamejs で直接 MP3 にエンコードします。音声 WebM の拡張子変更や WebM からの再圧縮ではありません。ステレオ 192kbps／モノラル 128kbps、音声コンテキスト 48kHz で要求します。ライブラリ・Worker・Worklet は同じサイト内から読み込み、音声を外部へ送りません。ステレオ録音には、録画と同様に 2ch と確認できる入力が必要です。最新の Chrome と HTTPS または localhost が必要です。

## WebM と MP4

動画の WebM は Chrome や対応プレーヤーで再生・保存でき、録画用途に使えます。ただし、一部の編集ソフトや共有先は MP4（H.264/AAC）のほうが対応範囲が広いです。すべてのアプリでの互換性は保証しません。現時点では動画は WebM、音声のみは MP3 で保存し、MP4 への変換機能はありません。

## Windows で接続できない場合

Windows の実機による再現確認は未実施です。画面のエラーに応じて次を確認してください。

- 権限エラー：Chrome のサイト設定でカメラ／マイクを許可。Windows の「設定 → プライバシーとセキュリティ → カメラ／マイク」で **デスクトップアプリのアクセス** も許可します。組織管理の端末では管理者ポリシーにより制限される場合があります。
- 解像度エラー：1080p に非対応の場合は **720p、必要なら 480p に自動調整して接続** します。調整後の設定と実際の解像度を表示します。すべて非対応の場合にのみエラーを表示します。
- 使用中・読み込みエラー：Teams、Zoom、カメラアプリ等を閉じ、USB 接続を確認します。
- マイクが 1ch：**モノラル** を選びます。2ch が確認できない入力ではステレオ収録できません。
- 映像が不要：**録音のみ** にすればカメラの接続や権限を要求しません。

## 解像度と音声について

- 解像度を `ideal` で希望値として指定し、ブラウザが対応する解像度を一度の接続で選びます。解像度制約を拒否するドライバーに限り 1080p → 720p → 480p の順で再試行します。設定欄も実際に接続できた解像度へ更新し、自動調整を表示します。権限拒否・使用中・音声や deviceId のエラーでは解像度を再試行しません。フレームレートは 30fps を希望し、実際の値を表示します。USB 帯域・デバイス・ChromeOS により変わります。
- ステレオは `channelCount: { ideal: 2 }` を要求し、`getSettings().channelCount` が 2 以上でなければ録画を禁止します。モノラル入力を左右に複製してステレオ扱いすることはありません。
- エコー除去、ノイズ抑制、自動ゲインを無効にして要求します。実際に提供される音声は OS／ドライバー／ブラウザに依存します。2ch メタデータだけでは左右に異なる信号があることを保証できないため、実機で左右を試し録りしてください。
- Web Audio の明示的なチャンネル設定でステレオは 2ch、モノラルは 1ch にして 動画の場合は MediaRecorder、録音のみの場合は MP3 エンコーダーへ渡します。ステレオ入力をモノラルにする場合は Web Audio の speaker downmix を使用します。
- WebM（VP9 または VP8 / Opus）を保存します。MP4 変換は含みません。Chrome の録画 WebM は再生ソフトによって長さの表示やシークに制約がある場合があります。
- 録画中はデバイスや録音モードを変更できません。デバイス切断時は録画を停止し、取得できたデータを保存できるようにします。

## 接続と切替

- 初回は `facingMode: user` を優先します。Front がない場合や向き情報のない USB カメラでは、利用可能なカメラを使います。選択したカメラは deviceId で指定します。
- カメラ／解像度の切替は **映像トラックだけ** を開き直します。マイク・音声グラフ・AudioContext を維持します。旧映像を video 要素から外して停止し、ドライバーが解放直後に NotReadableError を返した場合のみ 250ms 後に一度再試行します。
- マイク／ステレオ・モノラルの切替は **音声だけ** を開き直します。カメラを維持します。
- AudioContext の resume は最初のクリック／変更イベント内で開始し、権限・デバイスの非同期処理の後に開始することによる自動再生制限を避けます。
- 接続全体は **20 秒**、音声開始は **3 秒**、映像開始は **5 秒** で待機を打ち切ります。「接続をキャンセル」「再接続」から復帰できます。エラーには止まった工程を表示します。
- getUserMedia 自体には中断 API がないため、キャンセル・タイムアウト後にブラウザから返されたトラックは即時停止し、新しい接続に混入させません。キャンセル時点でブラウザの権限ダイアログや OS の処理自体を閉じられるわけではありません。
- デバイス一覧取得はプレビュー・録画準備を妨げないよう別に行い、3 秒で待機を終了します。必要なら「デバイスを再検出」で更新してください。

Windows／Chromebook の実機でのドライバー待ち時間は未計測です。下記のテストは合成デバイスと意図的に応答を止める処理を使っています。

## レベルメーターと画面

ダーク背景・紫／シアンのネオン配色、大きめの日本語ラベル・ボタンを使用します。L/R は独立した 24 セグメントの LED メーターです。入力の実ピークを dBFS に換算し、緑（−60〜−15 dBFS）、黄（−15〜−5 dBFS）、赤（−5〜0 dBFS）で表示します。色の境界はセグメント単位の概算です。数値と左右のラベルも表示し、色だけに依存しません。メーターは入力の監視用で、録音音量を変更するものではありません。

## Chromebook 実機の確認手順

クラウドの仮想デバイス検証と実機検証は異なります。ユーザーから Chromebook での基本動作報告はありますが、下記のチェックリストを開発側で実機確認したわけではありません。

| 確認 | 操作と期待結果 |
| --- | --- |
| 初回アクセス | 最新 Chrome で HTTPS または localhost を開き、権限を許可。映像と入力メーターが出る |
| 権限拒否 | 拒否すると対処メッセージが出る。サイト設定で許可後、再接続できる |
| カメラの切替 | 内蔵／USB を切り替え、実際の映像が切り替わる |
| マイクの切替 | 内蔵／USB を切り替え、選んだマイクへの入力でメーターが動く |
| 1080p | 対応 USB カメラで 1920 × 1080 を表示。保存ファイルもプレーヤーの詳細等で確認 |
| 非対応解像度 | 720p カメラで 1080p を選んでも 720p に自動接続。設定・表示・保存ファイルが 720p になる |
| ステレオ | 2ch 対応 USB マイクを選択。左だけ、右だけに音を入れ、保存動画をヘッドホンで聴いて左右の分離を確認 |
| 非対応マイク | 1ch のマイクでステレオを選ぶと開始不可。モノラルへ切り替えると録画可能 |
| モノラル | モノラル録画した動画が 1ch で保存される |
| 停止／再開 | 一時停止中の時間が加算されず、再開後の映像・音声が保存される |
| 端末保存 | ダウンロード完了後、Chromebook の「ファイル」で WebM を開いて映像・音を確認 |
| USB 抜去 | 録画が停止し、それまでの動画を保存可能。再接続できる |
| 録音のみ | カメラを拒否してもマイクだけで接続。録画から切り替えるとカメラ使用ランプが消える |
| MP3 | ステレオ／モノラルで録音し、ダウンロードした MP3 を「ファイル」から再生。ステレオの左右分離も確認 |
| 少し長い録画 | 1〜5分試し、音ずれ・空き容量・メモリを確認してから本番へ |

## 自動テスト

開発テストのみ npm 依存を使用します。Node.js 20 以降を推奨します。

```sh
npm ci
npm test
npm run test:browser
npm run test:connection
```

`test:browser` は Python 3、Chromium、FFmpeg と ffprobe が必要です。既定の Chromium パスは `/usr/bin/chromium`。別の場所では `CHROMIUM_PATH=/path/to/chromium npm run test:browser` とします。テストはポート 8765 を使用し、起動したサーバーと一時ファイルを終了時に削除します。

仮想カメラと左右で異なる周波数（L:440Hz / R:880Hz）の音源を使い、実際に収録・ダウンロードした WebM と MP3 を ffprobe と FFmpeg で解析します。1080p、ステレオの左右分離、モノラル 1ch、一時停止／再開、再生、デバイス切替、720p 切替、権限エラー、非対応解像度の自動調整と 720p 保存、3 色メーターの入力レベルへの反応、モノラル入力のステレオ防止、狭い画面での表示を検証します。MP3 のコーデック・チャンネル数・左右分離・一時停止を除いた長さ・再生・保存、カメラ権限を使わないこと、モード切替も検証します。物理 Chromebook／Windows／USB ドライバーの動作を代替するものではありません。

`test:connection` は Python 3 と Chromium を使い、ポート 8766 で実行します。Front 優先指定、6 回連続のカメラ切替でマイクと AudioContext を維持すること、マイク切替時のカメラ維持、一時的なドライバー使用中エラー、キャンセル後の遅い成功結果の停止、デバイス／音声／映像の応答停止からの復帰、デバイス一覧が応答しなくても接続が完了することを検証します。タイムアウト検証にはブラウザの仮想時計を使います。
